# 基金定投与分钟级缠论设计

**日期**：2026-07-29  
**状态**：已确认，待实施

## 1. 目标与范围

本次改造包含两个相互独立、共享现有 Web 应用外壳的功能：

1. 新增“基金定投”Tab，支持场外公募基金净值数据缓存、刷新和每周定投回测。
2. 扩展“缠论”Tab，在现有日线之外支持 30 分钟和 5 分钟级别。

第一版不包含：

- 货币基金定投；
- 场内 ETF 按基金净值定投；
- 月投、估值择时等其他定投策略；
- 交易费用、申购限额、暂停申购和赎回模拟；
- 分钟级中枢、走势类型或背驰等新增缠论算法；
- 实时行情推送。

## 2. 总体架构

沿用现有 `API -> Service -> Core` 三层结构，并隔离股票、基金和分钟行情的数据服务。

### 2.1 前端状态

顶部 `Header` 根据当前 Tab 切换输入模式：

- 技术分析、回测、指标测试、缠论：股票/ETF 代码；
- 基金定投：基金代码。

股票代码与基金代码分别保存。切换 Tab 不覆盖另一类代码，也不把基金代码发送给股票接口。

顶部动作仍为“分析”和“刷新数据”，但由 `App` 根据当前模式分发到明确的股票或基金回调。基金定投 Tab 不复用股票分析结果。

### 2.2 后端边界

新增独立模块：

- `fund_data_service`：基金元数据、净值和分红数据下载、标准化及缓存；
- `fund_investment_service`：基金定投回测编排；
- `fund_investment` core：定投日期选择、份额与收益计算；
- `minute_data_service`：分钟行情下载、缓存、刷新和范围裁剪。

现有缠论 core 算法不改变业务规则。`chan_service` 根据周期选择日线或分钟数据，并把完整时间戳传给现有 Bar、分型和笔流水线。

## 3. 基金数据

### 3.1 支持范围

第一版仅支持具有日度单位净值的场外公募基金。基金代码必须能在 AKShare 公募基金列表中识别，并能取得单位净值数据。

以下类型返回明确的“不支持”错误：

- 货币基金；
- 只有万份收益或七日年化、没有单位净值的产品；
- 场内 ETF；
- 已识别但没有可用净值数据的产品。

### 3.2 数据源

使用 AKShare 的东方财富/天天基金公募基金接口：

- 基金列表与类型用于代码和品种校验；
- `fund_open_fund_info_em` 的单位净值走势用于成立以来净值；
- 分红送配详情用于现金分红再投资；
- 拆分详情用于份额拆分和折算。

实测当前 AKShare 版本能够返回成立以来单位净值，例如：

- `000001`：2001-12-18 至 2026-07-29；
- `110022`：2010-08-20 至 2026-07-29。

上游网页接口并非稳定、受保证的正式数据 API。上游失败时必须保留旧缓存并返回可理解的错误。

### 3.3 文件格式

缓存路径：

```text
data/Fund_<六位基金代码>.csv
```

标准字段至少包括：

| 字段 | 含义 |
|---|---|
| 日期 | 净值日期，`YYYY-MM-DD` |
| 基金代码 | 六位代码 |
| 基金名称 | 基金简称 |
| 基金类型 | 上游基金类型 |
| 单位净值 | 当日单位净值 |
| 日增长率 | 上游披露值，可为空 |
| 每份分红 | 当日每份现金分红，无分红时为 0 |
| 拆分折算比例 | 新份额/旧份额，无拆分时为 1 |

数据按日期升序、日期唯一。数值字段必须验证为有限且单位净值大于 0。

### 3.4 加载与刷新

- 首次分析：本地文件不存在时下载成立以来全量数据。
- 刷新：重新下载全量历史，而不是只追加最新日期。这样可以接收历史净值修订和补录分红。
- 写入：先写同目录临时文件，校验并成功关闭后原子替换正式文件。
- 下载或校验失败：删除临时文件，保留原缓存。

## 4. 基金定投策略

### 4.1 参数

第一版只提供“每周定投”策略：

| 参数 | 默认值 | 规则 |
|---|---:|---|
| 定投星期 | 用户选择 | 周一至周五 |
| 每次金额 | 1000 元 | 大于 0，可修改 |
| 开始日期 | 用户选择 | 不早于基金首个净值日 |
| 结束日期 | 最新净值日 | 第一版不可修改 |

### 4.2 执行日期

按自然周计算，每周最多执行一次。

1. 找到该周用户选择的目标星期。
2. 若目标日有净值，使用目标日。
3. 若目标日无净值，使用该自然周内目标日之前最近一个有净值的日期。
4. 若该周在目标日之前没有任何净值，则跳过该周。
5. 不跨周寻找日期，也不使用目标日之后的未来净值。
6. 开始日期之前的日期不能被选为首次定投日。

例如选择周一但周一休市时，该周通常没有更早的工作日，因此跳过；选择周五而周五休市时，可提前至该周周四。

### 4.3 份额、分红与拆分

每次定投：

```text
购得份额 = 定投金额 / 当日单位净值
```

基金份额允许小数，不做 100 股整手限制。忽略申购、赎回和销售服务费用。

现金分红自动再投资：

```text
分红现金 = 分红前持有份额 * 每份分红
新增份额 = 分红现金 / 分红日单位净值
```

分红新增份额不计入用户累计投入。回测使用单位净值并显式处理分红，不使用累计净值替代，以免重复计算分红收益。

基金拆分或折算：

```text
拆分后份额 = 拆分前份额 * 拆分折算比例
```

例如上游记录 `1:1.4982` 时，比例解析为 `1.4982`。拆分不改变累计投入，也不直接产生收益。

同一日期存在多个事件时，固定顺序为：

1. 按拆分折算比例调整已有份额；
2. 按调整后的已有份额完成现金分红再投资；
3. 执行当日定投。

该顺序必须在实现和测试中保持一致。

### 4.4 结果

汇总字段：

- 基金代码和名称；
- 数据起止日期；
- 实际回测起止日期；
- 定投星期和单次金额；
- 定投次数；
- 累计投入；
- 当前持有份额；
- 最新单位净值；
- 当前市值；
- 累计收益额；
- 累计收益率。

计算公式：

```text
当前市值 = 当前持有份额 * 最新单位净值
累计收益额 = 当前市值 - 累计投入
累计收益率 = 累计收益额 / 累计投入
```

时间序列按每个净值日返回：

- 累计投入；
- 资产市值；
- 累计收益率。

交易明细按每次定投返回：

- 执行日期；
- 原计划目标日期；
- 是否发生提前；
- 单位净值；
- 投入金额；
- 购得份额；
- 定投后累计份额。

分红再投资记录作为独立明细返回，包含日期、每份分红、分红现金和新增份额。

拆分折算记录也作为独立明细返回，包含日期、拆分类型、折算比例、调整前份额和调整后份额。

## 6. 分钟行情数据

### 6.1 周期和覆盖范围

支持：

- `daily`：现有日线；
- `30`：30 分钟；
- `5`：5 分钟。

分钟数据目标覆盖最近两年。A 股必须支持；ETF 尽力支持，无法取得时明确提示当前标的不支持该周期。

### 6.2 数据源顺序

#### A 股

1. BaoStock 主数据源；
2. AKShare fallback。

BaoStock 无需 Token，支持 5/15/30/60 分钟和前复权。实测 `600519` 在 2024-07-29 至 2026-07-29 可返回：

- 5 分钟：23,280 条；
- 30 分钟：3,880 条。

#### ETF

使用 AKShare 分钟接口尝试获取。返回数据可能不足两年：

- 新浪接口实现固定请求 1,970 根；
- 实测 `600519` 的 1,970 根约对应 5 分钟两个月、30 分钟一年；
- 东方财富接口可能受网络、代理和上游限制。

ETF 如果仅取得部分目标区间，允许展示实际数据，但响应和界面必须明确显示真实覆盖范围；完全无数据则返回“不支持”而不是空图。

### 6.3 缓存

缓存路径：

```text
data/Minute_<代码>_5.csv
data/Minute_<代码>_30.csv
```

标准字段：

| 字段 | 含义 |
|---|---|
| 时间 | K 线结束时间，`YYYY-MM-DD HH:mm:ss` |
| 股票代码 | 规范化代码 |
| 周期 | `5` 或 `30` |
| 开盘 | 前复权开盘价 |
| 最高 | 前复权最高价 |
| 最低 | 前复权最低价 |
| 收盘 | 前复权收盘价 |
| 成交量 | 成交量 |
| 成交额 | 成交额，可为空 |
| 复权 | 固定记录 `qfq` |
| 数据源 | `baostock` 或具体 AKShare 来源 |

数据按时间升序、时间唯一。刷新时重新获取最近两年，标准化、排序、去重、裁剪后原子覆盖。

### 6.4 代码映射

BaoStock 使用带点市场代码：

- `6` 开头：`sh.<code>`；
- `0`、`3` 开头：`sz.<code>`；
- 北京市场按 BaoStock 实际支持情况映射，否则走 fallback。

ETF 不假定 BaoStock 支持，直接进入 AKShare fallback。

## 7. 分钟级缠论

### 7.1 后端

扩展缠论请求：

```json
{
  "stock_code": "600519",
  "period": "5",
  "start_date": "2026-04-01",
  "end_date": "2026-07-29"
}
```

`period` 只允许 `daily`、`30`、`5`。

数据选择：

- `daily` 调用现有 `load_stock_data`；
- `30`、`5` 调用分钟数据服务。

分钟 Bar 的 `date` 使用完整时间戳。包含关系、分型和笔算法继续复用现有 core。响应增加：

- `period`；
- 缓存数据的实际覆盖起止时间；
- 当前响应的起止时间；
- 数据源；
- 是否达到两年目标覆盖。

返回数据超过后端配置的最大条数时返回明确的 400 错误，提示缩小日期范围，不静默截断。

### 7.2 前端

缠论配置区新增周期选择：

- 日线；
- 30 分钟；
- 5 分钟。

默认日期范围：

- 日线：保持现有默认值；
- 30 分钟：最近一年；
- 5 分钟：最近三个月。

用户可在缓存覆盖范围内选择最长两年的任意区间。切换周期时根据周期设置合理默认范围并重新分析。

图表横轴和 tooltip：

- 日线显示日期；
- 分钟线显示日期和时间。

页面显示周期、数据源、实际覆盖范围、数据点数和笔数。ETF 部分覆盖时显示警告。

## 8. API

### 8.1 基金

#### `POST /api/fund/analysis`

请求：

```json
{ "fund_code": "000001" }
```

加载或下载基金数据，返回基金基本信息、最新净值及完整覆盖范围。

#### `POST /api/fund/refresh`

请求：

```json
{ "fund_code": "000001" }
```

强制刷新全量基金数据，返回行数和数据起止日期。

#### `POST /api/fund/backtest`

请求：

```json
{
  "fund_code": "000001",
  "strategy_name": "weekly_investment",
  "start_date": "2020-01-01",
  "weekday": 5,
  "amount": 1000
}
```

`weekday` 使用 1 至 5 表示周一至周五。

### 8.2 缠论

扩展 `POST /api/chan/analyze`，增加 `period`。

新增 `POST /api/chan/refresh`：

```json
{
  "stock_code": "600519",
  "period": "5"
}
```

只接受 `5` 或 `30`。日线刷新继续使用现有 `/api/data/refresh`。

## 9. 错误处理

错误应区分并向前端返回可操作信息：

- 代码格式无效；
- 基金不存在；
- 基金类型不支持；
- 基金没有单位净值；
- 上游数据源不可用；
- 下载结果为空或字段不完整；
- 缓存校验失败；
- 所选日期范围无数据；
- 数据不足以运行缠论；
- ETF 分钟数据不支持；
- 请求范围导致返回量超过限制。

API 层继续将输入和业务错误映射为 400/404，将非预期错误映射为 500。Service 不吞掉异常，也不返回成功形状的空数组。

## 12. 验收标准

1. 输入普通场外公募基金代码可取得成立以来净值并生成 `Fund_<代码>.csv`。
2. 基金刷新成功后更新本地文件，失败时旧文件不损坏。
3. 每周定投按指定星期、金额和开始日期执行，并遵守同周提前规则。
4. 分红以现金自动再投资方式增加份额，拆分按披露比例调整份额，结果可由明细复算。
5. 页面展示汇总、投入/市值曲线和定投明细。
6. A 股 5 分钟和 30 分钟缠论可使用最近两年缓存数据分析。
7. ETF 有数据时展示真实覆盖范围，无数据时给出明确提示。
8. 日线缠论结果不因多周期改造发生行为回归。
9. 后端目标测试通过，前端 TypeScript 检查和生产构建通过。
