# MAW + MACD 趋势增强策略设计

**日期**：2026-05-03
**状态**：用户已授权，待实施

## 1. 目标

新增 `trend_following_maw_macd`，优先捕捉中长线主升趋势的绝对收益，同时用长期成本趋势破坏避免灾难性回撤。保留既有 `trend_pullback_maw_macd` 作为防守型对照策略。

不以每只股票都跑赢买入持有为目标；验收依据固定历史比较中时间更晚留出窗口的平均/中位绝对收益与最大回撤。使用日线；“同日收盘成交”是用户选择的简化执行假设，可能造成结果偏差，且不代表真实可成交性。

## 2. 趋势状态

| 状态 | 条件 | 仓位目标 |
|---|---|---:|
| 强趋势 | Close > MAW20 > MAW60 > MAW120，MAW60 与 MAW120 均高于 20 日前 | 100% |
| 正常上升趋势 | Close > MAW60 > MAW120，MAW60 高于 20 日前 | 70% |
| 回撤恢复 | Close 从下方收复 MAW20，且 Close > MAW60 > MAW120，MACD Histogram 当日改善 | 85% |
| 趋势不完整 | 不满足上述条件 | 保持现有仓位，交由退出规则处理 |

MAW 使用现有换手率加权 VWAP 成本线，默认周期 20/60/120，斜率回看 20 日。MACD 使用 12/26/9，所有值仅使用截至当日的数据。

## 3. 开仓与加仓

- 初始开仓：正常上升趋势或强趋势第一次成立，且 MACD Histogram 高于前一日或 DIF 上穿 DEA；买入到状态目标仓位。
- 强趋势加仓：强趋势状态且当前仓位低于 95%，买入至 100%。不要求价格低于上次买入价。
- 回撤恢复加仓：回撤恢复状态且当前仓位低于 85%，买入至 85%。
- 所有买入之间至少相隔 5 个交易日；目标与当前仓位差低于 10 个百分点时不调仓。

## 4. 持有、减仓和退出

强趋势时不因 MACD 柱缩短、价格偏离 MAW20 或短期回落而止盈；其目标是让盈利奔跑。

按顺序每日至多执行一种动作：

1. **灾难止损清仓**：收盘价低于加权平均成本 25%。
2. **长期趋势清仓**：MAW60 < MAW120，或连续 3 日收盘低于 MAW120。
3. **中期趋势减仓**：连续 3 日收盘低于 MAW60，降至 30%。
4. **趋势转弱减仓**：收盘低于 MAW60 且 DIF < DEA 连续 3 日，降至 50%。
5. **加仓或开仓**：仅执行第 3 节规则。

部分减仓只有当前实际仓位与目标差至少 10 个百分点才成交；全清仓不受该限制。所有成交为收盘价、100 股整手，资金不可为负。

## 5. 无未来函数

每个 t 时点仅使用 `[0, t]` 数据计算 MAW、MACD 和趋势状态，随后在 t 日收盘价成交。交易记录 `signal_date` 必须等于 `date`。对任一截断点，完整样本和截断样本在该点前的指标、仓位和交易必须一致。

## 6. 评估协议

缓存 A 股中具备 `成交额`、`成交量`、`换手率` 的标的纳入评估；ETF 缺少 MAW 输入时明确跳过。固定划分：

- 开发历史窗口：2021-01-01 至 2023-12-31；
- 时间更晚的留出窗口：2024-01-01 至 2025-12-31（已被检查，不是未触及的 OOS 验证集）；
- 基线：buy_and_hold、three_factors、supertrend_ma、trend_pullback_maw_macd；
- 新策略：trend_following_maw_macd。

评估报告必须按标的和策略输出总收益、最大回撤、交易次数，并汇总时间更晚留出窗口的平均收益、中位数收益、平均最大回撤、跑赢买入持有的标的比例。这是固定历史比较；评估只用于研究，不执行参数选择或根据比较结果改写默认策略。

## 7. 产品接口

后端将新策略作为有效 `strategy_name`；沿用 MAW/MACD/目标仓位/实际仓位响应序列及交易明细。评估 CLI 在未传入 `--revision` 时记录当前 Git HEAD，直接函数调用仍可显式注入确定性 revision。前端回测策略下拉框增加“MAW+MACD趋势增强（实验）”，并说明强趋势可满仓、3 日中长期趋势退出、25% 灾难止损和当日收盘成交。

## 8. 验收

1. 强趋势可达 100% 仓位，且不会因短期 MACD 柱缩短自动减仓。
2. 所有退出、整手、费用、同日信号和无未来函数约束均有确定性测试。
3. 评估工具输出开发历史窗口与时间更晚留出窗口的固定历史比较报告，不自动优化参数。
4. 后端 pytest、前端构建和评估工具均成功运行。
